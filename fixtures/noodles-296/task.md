The asynchronous side has no owned indexed reader: callers pair reader and index manually. Add them to `noodles-sam`, `noodles-bam`, `noodles-cram`, and a unified reader in `noodles-util`, each exposing an `indexed_reader` module and `IndexedReader` re-export.

SAM and BAM own a CSI or BAI index, CRAM a CRAI index, each from `new` or `Builder::set_index`; `index` returns a `dyn csi::BinningIndex + Send + Sync` reference, readers remaining `Send` whenever their underlying readers are. SAM provides `new`, `get_ref`, `get_mut`, `into_inner`, `read_header`, `records`, `index`, `query`, `query_unmapped`, with `set_index`, `build_from_path`, `build_from_reader`. BAM adds `read_record_buf` and `read_record`, preserving the existing reader's byte count and record mutation. CRAM adds `reference_sequence_repository`, `read_file_definition`, `read_file_header`, `read_container`, and `set_reference_sequence_repository`, forwarded for decoding and queries, exposing cache changes.

An explicit index bypasses lookup. Otherwise path construction reads `<source>.csi` for SAM, `<source>.crai` for CRAM; BAM tries `<source>.bai` first, falling back to `<source>.csi` only on `NotFound`; a valid BAI prevents CSI inspection, every other BAI error returned unchanged. Without an index, reader construction returns `InvalidInput` with `missing index`.

The unified reader has exactly `Sam`, `Bam`, and `Cram` variants, dispatching `read_header`, `records`, `query`, and `query_unmapped`, yielding boxed `dyn sam::alignment::Record` values preserving the concrete reader's records, selections, and I/O errors, plus staged CRAM file definition, file header, and container reads. Its `Builder` adds `set_reference_sequence_repository`, `set_compression_method`, taking `Option<CompressionMethod>`, and `set_format`: independent explicit-or-detected settings, whichever unset being detected.

Detection must inspect enough input to decide even when a reader returns the signature one byte at a time: a short read is not end of input. Bytes consumed while detecting a reader-backed source are replayed to the selected reader, errors returned unchanged. Both wrapper types are nameable and constructible by an external caller: `build_from_reader` returns `IndexedReader<ReaderBackedSource<R>>`, so `alignment::r#async::io::indexed_reader` publicly exports `ReplayReader`, its constructor `ReplayReader::new(prefix: Vec<u8>, inner: R)`, and the alias `ReaderBackedSource<R> = BufReader<ReplayReader<R>>`. `ReplayReader` implements `AsyncRead` and `AsyncSeek` over the prefix-then-inner concatenation, emitting each prefix byte exactly once, relative seeks accounting for unread replayed bytes. Detection buffers at most 65536 bytes, requesting at most 8192 at a time, sized so the total never exceeds that bound: requests shrink near it, never reads more than needed, undecidable input failing with `UnexpectedEof`.

BGZF SAM and BAM are accepted; uncompressed returns `InvalidData` with `source not bgzip-compressed`. Uncompressed CRAM is accepted; BGZF CRAM returns `CRAM cannot be bgzip-compressed`. With compression explicitly BGZF and format unset, detection runs through the BGZF decoder: raw non-gzip input returns `invalid gzip header`. CRAM needs both the `CRAM` magic and a supported 3.0 or 3.1 version, so a headerless BGZF SAM record named `CRAMread` stays SAM, as does magic with unsupported version or truncated before the version bytes. Both detectors share this rule.

A wrong-family index is ignored during path construction so lookup proceeds, but produces `missing index` at reader construction. Associated-index failures propagate unwrapped, preserving kind and message.

The synchronous `alignment::io::reader::Builder` now detects BGZF CRAM as CRAM and rejects it, where it was previously misread as SAM. New readers begin at the minimum BGZF virtual position.
